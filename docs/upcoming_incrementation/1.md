

Design a **Bluetooth-assisted nearby group chat system** where groups are **manually created**, **presence is controlled by Bluetooth scanning**, and **group visibility is synced using the internet in real time**. These groups enable nearby communication, silent help, and social interactions such as birthday wishes.

* * *

Feature Overview
----------------

Users can manually create **nearby chat groups**. Group visibility and user presence are determined by **Bluetooth discovery**, while **group reflection and discovery** are handled via the internet. Groups are **temporary by proximity**, not by time.

* * *

Group Creation & Ownership
--------------------------

### 1. Manual Group Creation

* Only users can manually create groups (no automatic group creation).

* Each group has:
  
  * Group name
  
  * Creator (owner)
  
  * Active nearby users list (dynamic)

### 2. Creator Scanning Responsibility

* The **group creator’s phone continuously scans** for nearby users via Bluetooth.

* All nearby users running the app and discovered by the creator’s phone are:
  
  * Added to the group’s **live presence list** in the database.

* Presence updates happen **in near real-time**.

* * *

Bluetooth Presence Rules
------------------------

### 3. Auto Leave on Bluetooth Loss

* If a user’s Bluetooth is **not discovered for 10 seconds**, the system:
  
  * Automatically removes that user from the group presence list.

* If the creator’s Bluetooth stops scanning:
  
  * The group becomes inactive or hidden.

### 4. Single Group Creation Rule

* One user can create **only one active group at a time**.

* (Optional) Users may view multiple groups but only create one.

* * *

Nearby Groups Discovery (Internet-Based)
----------------------------------------

### 5. Database Reflection Logic

* The creator’s phone uploads the scanned nearby user IDs to the backend database **in real time**.

* When any user opens the **Nearby Groups page**:
  
  * The app queries the database to find:
    
    * All groups where the user’s ID exists in the scanned presence list.
  
  * All matching groups are displayed.

> Users do NOT join groups — presence is implicit via proximity.

* * *

Chat Access Rules
-----------------

### 6. Open Chatroom Model

* Users are free to:
  
  * Open any nearby group chatroom they are visible in.
  
  * Read all messages.
  
  * Send messages without explicitly “joining” the group.

* Leaving range automatically revokes access.

* * *

Group Lifecycle
---------------

### 7. Group Visibility & Expiry

* A group exists as long as:
  
  * The creator is actively scanning.
  
  * At least one nearby user is detected.

* If no users are detected or creator goes offline:
  
  * The group disappears from Nearby Groups.

* * *

Silent Help & Social Use Cases (Built on Same System)
-----------------------------------------------------

### 8. Silent Help (Danger Use Case)

* A user can send a **silent help message** inside any nearby group.

* Nearby users receive it instantly without alarms or public alerts.

* Identity can be:
  
  * Anonymous, or
  
  * Revealed based on user settings.

### 9. Social Use Case (Birthdays & Support)

* Nearby users can:
  
  * Wish birthdays silently
  
  * Send supportive or check-in messages

* No direct connection required — proximity enables visibility.

* * *

Privacy & Safety
----------------

* No GPS storage required.

* Bluetooth-based presence only.

* Auto-removal on signal loss ensures no lingering access.

* Block/report options inside chatrooms.

* * *

Key Objectives
--------------

* Enable **real-time nearby communication**

* Use **Bluetooth for presence, internet for scale**

* Remove friction (no join/leave buttons)

* Support safety and social moments silently

* Ensure proximity-based privacy

* * *

Optional Enhancements
---------------------

* Creator handover if creator leaves

* Rate limiting for messages

* Temporary moderation controls

* Visual indicator for signal strength

* Emergency escalation (opt-in)
